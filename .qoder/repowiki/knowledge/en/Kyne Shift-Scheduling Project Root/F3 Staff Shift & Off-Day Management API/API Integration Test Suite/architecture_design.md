Tests live under `api/test/` as Jest specs matching `.api-spec.ts`, driven by a dedicated `jest-api.json` config (ts-jest transform, `testEnvironment: node`, single worker, 30s timeout, coverage collected against `../src/**`). `setup-env.ts` is a Jest `setupFiles` hook that pins `SUPABASE_URL` before `AppModule` imports. Each spec file (`health.api-spec.ts`, `auth.api-spec.ts`, `employee.api-spec.ts`) follows the same seam pattern: `Test.createTestingModule({ imports: [AppModule] })` then `overrideProvider(SUPABASE_JWKS)` with `jose`'s `createLocalJWKSet` + generated ES256 key pair, and `overrideProvider(PrismaService)` with an in-memory fake implementing only the methods exercised by the route under test; the app is created via `moduleRef.createNestApplication()` and hit through `supertest`. `request.api-spec.ts` provides shared request helpers used across specs. Dependency direction is one-way: tests import from `../src/app.module` and selected providers but are excluded from coverage collection.
