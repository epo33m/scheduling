Each subdirectory is an independent Claude Code / OpenAI-compatible skill: a `SKILL.md` front-matter document describing the prompt-driven workflow, plus an `agents/openai.yaml` declaring the model/agent configuration. There is no shared runtime code — the module is purely declarative skill definitions consumed by an outer agent framework. The skills fall into two groups:
- Repo bootstrapping: `setup-matt-pocock-skills` writes `docs/agents/{issue-tracker,domain,triage-labels}.md` and augments `CLAUDE.md`/`AGENTS.md`; `setup-pre-commit` installs Husky + lint-staged + Prettier; `git-guardrails-claude-code` copies `scripts/block-dangerous-git.sh` into `.claude/hooks/` and merges a `PreToolUse` hook into `.claude/settings.json`.
- Workflow templates: `pr` provides a PR-body template with Summary/Evidence/Merge Danger sections; `migrate-to-shoehorn` documents replacing `as` assertions with `@total-typescript/shoehorn`; `scaffold-exercises` guides exercise generation; `teach` defines a stateful learning workspace (`MISSION.md`, `RESOURCES.md`, `learning-records/*.md`, `lessons/*.html`, `assets/*`) with its own format specs; `setup-ts-deep-modules` uses `dependency-cruiser.config.cjs` to enforce module boundaries.
Dependency direction is one-way: skills read from the host repo (`.git/config`, `package.json`, existing docs) and write configuration files back; they do not import each other.
