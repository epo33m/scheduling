The schema is split across per-entity files under `schema/` (`employee.prisma`, `schedule_week.prisma`, `shift_type.prisma`, `off_request.prisma`, `shift_request.prisma`) referenced from a minimal root `schema/schema.prisma` that only configures the Prisma 7 generator (output to `../../src/generated/prisma`, CJS module format) and the PostgreSQL datasource; the connection string lives in `prisma.config.ts` as noted by the comment. Domain enums (`EmployeePosition`, `EmployeeRole`, `EmployeeStatus`, `WeekStatus`, `RequestStatus`, `ShiftCode`) live alongside their models. Referential integrity uses explicit `@relation(... onDelete: Cascade)` declarations on child models (`OffRequest`, `ShiftRequest`). Database table names are explicitly mapped via `@@map`. Versioned SQL migrations live under `migrations/<timestamp>_<slug>/migration.sql` with a `migration_lock.toml`. `seed.ts` bootstraps the `shift_type` catalog using `SHIFT_TYPE_CATALOG` from `@repo/types`, validated through `shiftTypeSeedSchema` from `@repo/validators`, and connects via a raw `pg.Pool` wrapped in `PrismaPg` adapter rather than the generated client's default connection.
